# Map Task Columns

Maps your Linear workspace's columns to Glori Builder's canonical pipeline state keys and writes
the result into the project `.claude/CLAUDE.md`. Every pipeline command reads this map to know
which Linear column each stage moves an issue to.

Run once per project. Rerun only if you rename, add, or remove columns.

See `.claude/docs/linear-states.md` for what each canonical key means and the full state machine.

## Step 0: Prerequisites

```bash
echo "${LINEAR_API_KEY:+set}"
```

If empty, stop: "Set LINEAR_API_KEY (run /quetrex-setup or /secrets add LINEAR_API_KEY)."

## Step 1: Identify the team

If `$ARGUMENTS` contains a team key, use it. Otherwise ask: "What's your Linear team key? (the
prefix on issue IDs, e.g. SMA in SMA-57)".

Look up the team UUID:

```bash
curl -s -X POST https://api.linear.app/graphql \
  -H "Authorization: $LINEAR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "{ teams(filter: { key: { eq: \"TEAM_KEY\" } }) { nodes { id key name } } }"}'
```

If no team is found, report it and stop.

## Step 2: Fetch all workflow states

```bash
curl -s -X POST https://api.linear.app/graphql \
  -H "Authorization: $LINEAR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"query": "{ team(id: \"TEAM_UUID\") { states { nodes { id name type position } } } }"}'
```

Display every state with its name and type, sorted by `position`, so the user sees their actual
board:

```
Your Linear columns ({team name}):
  Backlog              (type: backlog)
  AI: Needs Clarity    (type: unstarted)
  Queued               (type: unstarted)
  AI: In Progress      (type: started)
  AI: Rework           (type: started)
  AI: PR Ready         (type: started)
  Deployed             (type: started)
  Merged               (type: started)
  Complete             (type: completed)
  Cancelled            (type: cancelled)
  Duplicate            (type: cancelled)
```

## Step 3: Propose a mapping

For each canonical key, propose the best-matching column using name keywords first, then type.
Heuristics (case-insensitive, match on the user's actual column names):

| Key | Match hints |
|---|---|
| `backlog` | name "backlog"; else lowest-position `backlog`/`unstarted` |
| `queued` | name "queued"/"todo"/"ready to start"; type `unstarted` |
| `in_progress` | name "in progress"; type `started` |
| `needs_help` | name "needs clarity"/"blocked"/"needs help"/"question" |
| `rework` | name "rework"/"changes needed" |
| `ready` | name "pr ready"/"in review"/"review" |
| `merged` | name "merged" |
| `deployed` | name "deployed"/"staging"/"shipped" |
| `complete` | name "complete"/"done"; type `completed` |

Present the proposal as a table and ask the user to confirm or correct each row. Let them map a
key to "none" if their workspace genuinely lacks that column (e.g. no separate Deployed) — record
it as unmapped and note which commands will fall back to type lookup.

```
Proposed mapping — confirm or tell me what to change:

  backlog      → Backlog
  queued       → Queued
  in_progress  → AI: In Progress
  needs_help   → AI: Needs Clarity
  rework       → AI: Rework
  ready        → AI: PR Ready
  merged       → Merged
  deployed     → Deployed
  complete     → Complete

Look right?
```

Wait for confirmation. Apply any corrections. Validate every chosen column name exactly matches a
real state name from Step 2 — if a name doesn't match, re-prompt; never invent a name.

## Step 4: Write the map into project CLAUDE.md

The map lives in the project `.claude/CLAUDE.md` as a `## Linear States` section so the agents
that already read that file pick it up. If a `## Linear States` section already exists, replace
it; otherwise append it.

```markdown
## Linear States
<!-- Generated by /map-task-columns. Maps Glori Builder canonical keys to this workspace's columns. -->
<!-- Team: {TEAM_KEY}. Rerun /map-task-columns if columns change. -->
| Key | Column |
|---|---|
| backlog | {Backlog} |
| queued | {Queued} |
| in_progress | {AI: In Progress} |
| needs_help | {AI: Needs Clarity} |
| rework | {AI: Rework} |
| ready | {AI: PR Ready} |
| merged | {Merged} |
| deployed | {Deployed} |
| complete | {Complete} |
```

Omit any row the user mapped to "none".

If `.claude/CLAUDE.md` does not exist, tell the user to run `/create-rules` first, but still offer
to create a minimal file containing just this section.

## Step 5: Commit

```bash
git add .claude/CLAUDE.md
git commit -m "chore: map Linear columns to Glori Builder pipeline states"
```

Note: if the project enforces feature branches and you are on `main`, create a branch first
(`git checkout -b chore/map-task-columns`) before committing.

## Step 6: Confirm

Report the final mapping table and:

> Linear state map saved to `.claude/CLAUDE.md`. The pipeline now moves issues through these exact
> columns. Automation runs queued → AI: PR Ready and stops; `/merge-issue`, `/deploy`, and
> `/complete` are the manual gates after that.

## Notes

- Exact name matching is what makes this reliable — several of your columns likely share Linear
  `type: "started"`, so type alone can't tell them apart. The map fixes that.
- Rerun any time columns change. The pipeline always reads the current map.
- See `.claude/docs/linear-states.md` for the canonical keys and the full state machine.
