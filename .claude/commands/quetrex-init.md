# Initialize Quetrex + Zikaron for this project

Bind the current directory to a Quetrex project so its activity feeds Zikaron memory. Handles brand-new projects (creates the Quetrex project row and the `.quetrex.yaml` manifest) **and** existing Quetrex projects (links this checkout to a project that already exists).

When this skill finishes, every Claude Code conversation started in this directory — and every agent run dispatched by Quetrex for this project — will write episodes to Zikaron at this project's scope, and recall/teach from the same scope.

## Inputs you may collect

- Quetrex instance URL (default: `http://127.0.0.1:3100`)
- Company (pick from the list returned by the instance; skip if there's only one)
- Project (pick an existing one from the list OR create a new one)
- New project name (default: current directory basename)

Use the AskUserQuestion tool for every interactive pick.

## Instructions

### Phase 1 — Preflight

1. **Check for an existing `.quetrex.yaml`:**
   ```bash
   test -f .quetrex.yaml && cat .quetrex.yaml
   ```
   If one already exists:
   - Read it, display `companyName` + `projectName` + `projectId`.
   - Ask the user: "This project is already linked. Re-link to a different Quetrex project? (yes/no)" via AskUserQuestion.
   - If no → confirm and exit: "Already initialized. Zikaron is active for this project."
   - If yes → continue; Phase 6 will overwrite the file.

2. **Resolve the Quetrex instance URL.** Default to `http://127.0.0.1:3100`. If `QUETREX_URL` env var is set, use that.

3. **Health check:**
   ```bash
   curl -sS ${QUETREX_URL:-http://127.0.0.1:3100}/api/health
   ```
   - Must return `{"status":"ok", ...}`.
   - If the request fails: stop and tell the user: "Quetrex server is not running. In the `quetrex-cloud` repo, run `pnpm dev`, then re-run `/quetrex-init`."

### Phase 2 — Select or confirm company

4. **List companies:**
   ```bash
   curl -sS ${QUETREX_URL:-http://127.0.0.1:3100}/api/companies
   ```
   - If the response is `[]`: stop and tell the user: "No companies exist on this Quetrex instance. Open the dashboard at the instance URL, complete onboarding to create your first company, then re-run this skill."
   - If there is exactly one company: auto-select it. Record `companyId` and `companyName`.
   - If there is more than one: show the list as `{name} ({id})` and ask the user to pick one via AskUserQuestion.

### Phase 3 — Select or create project

5. **List existing projects for the company:**
   ```bash
   curl -sS ${QUETREX_URL:-http://127.0.0.1:3100}/api/companies/${companyId}/projects
   ```

6. **Decide: link existing vs. create new.**
   - Present the user with AskUserQuestion:
     ```
     Link this directory to:
       1. An existing Quetrex project (pick from list below)
       2. A new Quetrex project (create now)
     ```
     If any existing projects were returned, list them by name. If none, skip straight to option 2.

7. **If linking to existing**, ask the user to choose one and record `projectId` + `projectName`.

8. **If creating new:**
   - Propose a name: the basename of the current working directory (e.g., `basename "$(pwd)"`).
   - Ask via AskUserQuestion: "Project name? (default: `<basename>`)" — accept the default if the user is silent.
   - Create the project:
     ```bash
     curl -sS -X POST ${QUETREX_URL:-http://127.0.0.1:3100}/api/companies/${companyId}/projects \
       -H 'content-type: application/json' \
       -d '{"name":"<project name>"}'
     ```
   - Extract `id` and `name` from the response → `projectId` + `projectName`.

### Phase 4 — Write `.quetrex.yaml`

9. Write the manifest to `.quetrex.yaml` at the repo root. Use the Write tool:

   ```yaml
   # .quetrex.yaml — Quetrex + Zikaron project identity.
   # Generated by /quetrex-init. Commit this file to your repo so every
   # checkout and every agent shares the same scope.
   version: 1

   quetrex:
     instance: http://127.0.0.1:3100
     companyId: <uuid>
     companyName: <company name>
     projectId: <uuid>
     projectName: <project name>

   zikaron:
     # Zikaron captures Claude Code session files and every agent run started
     # in this directory. Memories surfaced during a run are scoped to this
     # project, its parent company, and the Quetrex instance.
     scope: project
     captureSessions: true

   initializedAt: <ISO-8601 timestamp>
   ```

   Replace the placeholders with the real values resolved in earlier phases. Use ISO-8601 UTC for `initializedAt` (e.g., the output of `date -u +%Y-%m-%dT%H:%M:%SZ`).

### Phase 5 — Make sure it's committed

10. **Do NOT gitignore `.quetrex.yaml`.** Check the repo's `.gitignore`:
    ```bash
    grep -E "\\.quetrex\\.yaml" .gitignore 2>&1 || echo "not ignored"
    ```
    - If the file is ignored: ask the user to confirm, then remove the entry (this file must be committed so the team shares scope).

11. **Check `.claude/skills/` for a matching Claude Code skill.** Not required — optional polish. Only do this if the user has other projects where they invoke `/zikaron-status` or similar. Skip if not applicable.

### Phase 6 — Confirm & next steps

12. Tell the user:

    > **Linked to Quetrex + Zikaron.**
    >
    > - Instance: `<url>`
    > - Company: `<name>` (`<id>`)
    > - Project: `<name>` (`<id>`)
    > - Manifest: `.quetrex.yaml`
    >
    > From now on:
    > - Every Claude Code conversation started in this directory feeds Zikaron at this project's scope (via the session ingester).
    > - Every Quetrex-dispatched agent run for this project composes a Zikaron bundle into its system prompt.
    > - Teach Zikaron facts at this scope via the dashboard at `<url>/zikaron/memories`, the `/zikaron/corrections` endpoint, or the MCP server (`quetrex` MCP) if installed.

## Failure modes to handle cleanly

- **Quetrex server not reachable:** tell the user exactly how to start it; do not write the yaml.
- **No companies:** tell the user to complete UI onboarding first; do not create companies from this skill.
- **Project create fails:** surface the API error verbatim and stop; do not write a partial yaml.
- **User aborts at any AskUserQuestion:** exit cleanly, change nothing.

## Do NOT

- Do not modify the Quetrex instance beyond creating a single project when explicitly requested.
- Do not touch `CLAUDE.md`, `.cursor/rules`, or any other tool's memory file — this skill is only about Quetrex + Zikaron linkage.
- Do not write `.quetrex.yaml` until all selections are confirmed.
